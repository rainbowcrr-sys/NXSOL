# libnxicons 不可删除

`libnxicons.so`（以及它的拆分变体）是窗口框架的一部分。它以不可变方式安装：任何账户都删不掉、替换不了，**root 也包括在内**，维护模式是唯一能碰它的地方。

这不是一条"以后可以收紧"的权限策略。它是在说明这些文件是什么：**没有它们就画不出窗口框架**，所以系统不允许出现"它们不在"的状态。

---

## 为什么几何数据要编译进去

发图标最顺手的做法是字体文件，`icons/gen_font.py` 也确实还在生成 `nxicons.ttf`。但字体是文件，而文件有失败模式：

- 它可能不存在
- 它可能损坏
- 它的加载可能比第一帧需要的时间更慢

任何一种都会让窗口上"关闭"按钮的位置留一个空白，或者一个缺字符的方框。窗口框架不能有这种状态，所以轮廓是**库里的静态数组**。`nxicons.ttf` 照旧生成，给文档和想要真正字体的应用用，但合成器里没有任何东西读它。

---

## 在维护模式下删掉会怎样

维护模式允许你删。也只有那儿允许。下面三个后果，按通常被注意到的顺序：

### 1. 图标根本看不懂

每个图标变成空白或缺字符方框。红绿灯是三个空圆圈。你还能靠位置猜出哪个是哪个，这是窗口还能用的唯一原因。

### 2. 窗口变形

含图标的窗口会为图标预留空间。图标没了，布局引擎还留着那份预留却没什么可测量，于是周围元素挤过来填。运行对话框（`NX + R`）最明显：文字框旁边有个图标，没了它文字框就拉长去占那个空位 —— 对话框明显变长。

### 3. 崩溃

这是最常见的，不是最罕见的。绘图代码会调进这个库、期待拿回一个字形。库不在了，调用在加载时就失败，需要它的进程就死。因为合成器需要它，这通常意味着**桌面**而不是单个应用。

---

## 怎么恢复

用安装 U 盘启动，选维护，重装这个包。没有原地修复这条路，因为执行修复的工具正是缺掉的那个。

---

## 规则，说一次

| | |
|---|---|
| 谁能删 | 没有人，root 也包括 |
| 谁能换 | 没有人，root 也包括 |
| 哪儿能碰 | 仅维护模式 |
| 为什么 | 没有它画不出框架 |

想换图标，改 `icons/svg/` 里的 SVG 再重新生成。这是受支持的方式，不需要删库。
