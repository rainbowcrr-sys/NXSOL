# NX 安装器

安装器负责把"正在运行的 ISO"变成"装好的系统"：分区、写入、装引导、创建第一个用户。

它和 OOBE 不是一回事。安装器在系统还没写进硬盘时跑；OOBE 在装好的系统第一次开机时跑。两者都要选语言，这是故意的 —— 见"为什么语言问两次"。

---

## 怎么进入

ISO 启动后先进 live 桌面。桌面上有一个图标：

```
    Install NXSOL
```

图标是光盘 —— 用 NXIcons 画，不是 emoji。双击启动安装器。那个桌面上没有别的东西会启动安装。

**为什么先进 live 桌面**，而不是启动直接进安装器：从没见过 NX 的人可以在把自己的硬盘交给它之前先看看。安装器是众多图标中的一个，不是这张盘的全部性格。

---

## 步骤

Ubuntu 式的，因为这个形状大家熟，而且每一步确实是不同的决定：

| # | 步骤 | 说明 |
|---|------|------|
| 1 | 语言 | 默认英文。选了**立刻生效** —— 下一屏已经是新语言，不用重启 |
| 2 | 键盘布局 | 布局 + 变体 |
| 3 | 网络 | 网络安装版需要；离线版静默跳过 |
| 4 | 安装类型 | 最小 / 完整 |
| 5 | 磁盘 | 见下 |
| 6 | 时区 | 地图或列表 |
| 7 | 用户 | 仅本地账户 |
| 8 | 确认 | 汇总，然后开始装 |

### 语言原地切换

第 1 步是安装器唯一会重载自己的地方。所有字符串都在翻译表里，所有控件都从表里重建，所以选了简体中文，你眼前这个窗口立刻换成中文。没有"重启以应用"。

### 只有本地账户

第 7 步创建本地账户。没有在线登录、没有云账号、建用户不要求联网。这台机器拿来干什么，上面的第一个账户都属于拿着它的人。

---

## 磁盘

用 `os-prober` 扫描。安装器不自己解析分区表 —— 那个问题的边界情况太多（OEM 恢复分区、各种状态的 Windows、已有的 Linux、加密卷），不值得重写，而猜错就意味着可能覆盖掉什么。

检测到已有 Windows 时，界面上是：

```
    (•) 与 Windows 共存安装        <- 预选
    ( ) 用 NX System 替换 Windows
    ( ) 手动分区
```

共存是预选但不强制：三个选项都只差一次点击。在确认那一步之前，什么都不写。

## 系统镜像从哪来

| 介质 | 来源 |
|------|------|
| 离线 ISO | 镜像就在 ISO 里，跟安装器放一起 |
| 网络安装 ISO | 第 3–5 步用 `tools/nxfetch.py` 下载 |

两者最终落在同一个位置，所以安装器其余部分不关心是哪一种。

### 下载，以及为什么装不出一个损坏的系统

镜像切成卷，这样才能放在单文件 2 GiB 限制下托管。**分卷本身不是安全保证，校验才是**：

1. 先取 `manifest.json`，它是唯一的真相来源
2. 每一卷到达即算哈希 —— 坏卷只重下那一卷
3. 拼起来
4. 对拼好的镜像算哈希，跟 manifest 比
5. **只有匹配**才解包、才写入硬盘

所以传输出错丢一个字节，不可能产出一个装好的系统。它只会产出一个错误提示和一个暂存目录里的半成品。烦人，但不危险。

下载中断可续传。卷不完整 → 续传；卷完整但内容错 → 丢弃重下。两者用同一个方式发现：哈希。

## 装完之后

重启。装好的系统开机跑 OOBE —— 那是另一个程序，有另一个用途，见 `oobe/`。

### 为什么语言问两次

这是同一个外衣下的两个不同问题：

| | 安装器 | OOBE |
|---|---|---|
| 何时跑 | 系统还不存在时 | 装好的系统上，一次 |
| 选的语言是 | 安装器自己的 | 系统的默认语言 |
| 给谁 | 正在装系统的人 | 用这台机器的所有人 |

安装器需要一个语言才能跟你说话。OOBE 给一个会比安装行为活得更久的系统设默认值。
